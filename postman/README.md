# Postman Collection

Коллекция Postman предназначена для тестирования API системы управления доступами.

## Collections

В проекте используются две коллекции.

### 1. Seed Collection

Коллекция для первоначального наполнения базы данных.

Используется для создания основных сущностей:

- Resource
- Access
- Right Group
- связи групп и доступов
- конфликтующие группы

Рекомендуется запускать перед основным тестированием.

### 2. API Test Collection

Основная коллекция для тестирования API.

Поддерживает все сценарии использования (эндпоинты):

- создание заявок;
- выдача и отзыв прав;
- получение effective permissions;
- обновление статуса заявки.

## Environment

Переменные окружения находятся в папке:

```text
environment/
```

в формате Postman Environment JSON.

## Перед тестированием

Перед использованием Postman Collection необходимо запустить приложение и все зависимости.

Запускаем в корне проекта:
```bash
docker compose -f docker-compose.yml up -d
```

После запуска убедитесь, что:

API Gateway доступен
Access Management Service запущен
Validation Service подключён к Kafka
PostgreSQL и Kafka работают корректно

После этого можно импортировать Postman Collection и Environment и приступать к тестированию.

## Иморт коллекций

1. Открыть Postman;
2. В левом верхнем углу нажать collections, там же рядом import;
3. Импортировать:

   * collection JSON
   * environment JSON

## Использование

Рекомендуемая последовательность тестирования:

1. Создание Resource;
2. Создание Access;
3. Создание Right Group;
4. Добавление Access в группу;
5. Добавление конфликтов;
5. Создание заявки;
6. Проверка статуса заявки;
7. Получение прав пользователя.

## Дополнительно

* Все запросы выполняются через API Gateway
* Некоторые операции запускают асинхронную обработку через Kafka
* Для проверки результата может потребоваться повторный запрос статуса заявки
